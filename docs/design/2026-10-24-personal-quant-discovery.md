## 现状与目标差距（代码事实，不是用户需求）

- 当前 `apps/web/src/App.tsx` 以 14 个独立页面组织研究、报告、审核和模拟；不是围绕同一品种联动的交易工作台。
- 公开行情目前是三交易所 BTC/ETH 的 ticker 与 1h/48 根行情缓存；有手动源刷新，不等于持续流式盘口订阅。
- 当前余额图与公开行情 SVG 无法等同专业可缩放 K 线、成交标记、盘口深度及多窗联动系统。
- 历史回测、任务队列、结果核验、报告、模拟生命周期可作为改造基础；不要因 UI 重设计而丢失现有实验数据。
- FreqAI 历史预测与独立 PPO 研究已有实际产物，但不能将其当成已实现在线策略模型。
- 当前新闻主要用于带来源的研究草稿；尚未形成历史可用的新闻因子训练、回测、在线决策链路。
- 实盘控制仍是默认关闭、离线测试范围；公开多交易所观察不代表多交易所私有订单接入。

源码定位：行情 `quantpilot/exchange_data.py`、`apps/web/src/ExchangePanel.tsx`；研究约束 `quantpilot/research.py`；模拟 `quantpilot/deployments.py`；预测展示 `apps/web/src/MlPanel.tsx`；RL 协议 `quantpilot/rl_config.py`；新闻 `quantpilot/news_data.py` / `news_analysis.py`。研究配置目前固定 1h、SmaTrend/FreqaiTrend、BTC/ETH；无盘口深度/逐笔流接口、无手动下单/撤单前端。要实现交易终端业务，不能只修改主题和布局。

开源复用事实见 `docs/mvp2-open-source.md`：已使用 Freqtrade/FreqAI、CCXT、Stable-Baselines3、Gymnasium、PyTorch；FinRL/FinGPT 是参考，Qlib/RD-Agent/RSSHub 未接入。后续逐项核对功能收益、接口、维护成本和许可，再决定复用方式，不预先把所有项目合并。

## 新闻 C 的工程核查

- 预测模型有直接接入点：`strategies/FreqaiTrend.py::feature_engineering_standard`；RL 有接入点：`quantpilot/rl_env.py::features`。技术上不需要因为新闻因子就替换整套引擎。
- 共用数值因子计算规则，可考虑窗口新闻数、事件分类计数、距最近事件时间；情绪因子需可信提取来源。`unknown` 不等于中性 0。
- 历史与当前运行必须按同一截止时间、资产映射、修订处理、缺失规则和特征顺序计算；新加入新闻的模型应重新训练、冻结 schema 和归一化器，旧六维 PPO 不可直接复用。
- 现有新闻列表面向当前浏览，不适合直接作历史 as-of 查询：必须先筛截止前可用版本，再选当时最新修订，不能先选择今天的最新版本。
- 必须区分“此时段已覆盖但无事件”与“此时段没采集/源失败”；不能将采集失败直接填为无新闻。
- 新闻数据访问与历史到达时间仍是需要实际小样本验证的前置依赖；工程可接入不等于已拿到足量合格历史数据，也不等于新闻能提高收益。

## 开发流程建议（待确认，不是已批准实施排期）

| 阶段 | 产物 | 进入下一阶段的依据 |
|---|---|---|
| 1. 需求访谈 | 用户场景、优先级、决定与未决事项 | 用户确认需求理解一致 |
| 2. 针对性调研 | UI 参考对照、GitHub 复用矩阵、可行性小验证 | 每个依赖有具体用途，不以堆仓库代替需求 |
| 3. 交互原型 | 首页/交易/策略/AI 工作流的可点击原型 | 用户实际操作并确认布局与交互；原型模拟数据明确标注 |
| 4. 规格与技术设计 | PRD、SRS、业务状态图、数据/API、迁移方案、验收矩阵 | 每项需求可观察、可测试，区分本期/后续 |
| 5. 分阶段实施 | 按端到端业务流程逐步交付，可回退版本 | 各阶段同时验证前端、后端与数据来源 |
| 6. 集成验收 | 回归、故障路径、性能测量、演示数据与操作文档 | 用户实际操作验收；未验证能力明确列出 |

文档建议分工：PRD 说明为什么做、为谁做；SRS 说明必须有什么行为；技术设计说明如何实现；实施计划给出文件级任务、依赖和验证命令；验收矩阵关联需求、用例与证据。
