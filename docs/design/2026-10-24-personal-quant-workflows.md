# 个人量化工作台：业务流程与阶段验收草案

状态：根据 Q1–Q16 形成的设计草案；需求未最终冻结，不作为未经确认的完整实施规格。
关联：[需求与决定记录](2026-10-24-personal-quant-discovery.md)。

## 产品主线

**选择品种与准备数据 → 创建策略 → 训练/回测 → 比较与选版本 → 独立资金模拟 → 查看决策、持仓与结果。**

规则、RL、预测模型属于同一策略工作流的不同类型，不再让用户在彼此割裂的实验室中重复填写相同配置。新闻同时提供浏览、可解释风险规则、数值研究因子；新闻 C 不以阅读页或风险提示替代。

## 界面组织建议

| 工作区 | 用户任务 | 主信息与操作 |
|---|---|---|
| 策略工作台（首页） | 查看并管理正在运行的实例 | 左侧自选/策略实例；中央小时 K 线/指标/买卖点；右侧策略动作、模型状态、新闻与运行控制；底部持仓/订单/成交/日志 |
| 策略配置与版本 | 创建、复制、修改策略 | 规则/RL/预测类型、单品种、资金与风险配置、数据选择；保存草稿与版本，运行中的版本不被直接覆盖 |
| 训练与回测 | 启动任务、跟踪进度、比较结果 | RL/预测训练任务、区间、参数、取消与失败原因；规则直接回测；查看全部候选，不伪造训练进度 |
| 新闻与因子 | 理解事件及检验其作用 | 品种关联、事件列表、数据覆盖、因子随时间变化、启用/关闭新闻的对照；从策略信号反查原事件 |
| 数据与设置 | 补齐数据并核对连接 | 可选现货品种、下载任务、可用区间、服务状态、可选模型配置、资源限制 |

这是交互原型的起点，具体菜单数量、面板尺寸、标签名称由可点击原型确认。报告/审核证据移到对应策略和运行详情；必要校验仍由后端执行，界面主线不要求用户把审计当成日常主要工作。

## 场景一：新建规则策略

1. 新建 → 规则策略 → 选择品种。
2. 如果历史数据不齐，创建下载任务，显示实际进度和失败原因；下载未完成不能宣称可回测。
3. 填写参数、区间、虚拟资金和风险参数，保存策略草稿。
4. 运行回测，查看图表上的交易与逐笔结果；修改配置会创建新版本，不改变已保存结果。
5. 选定版本并完成必要运行校验后，显式启动模拟。

## 场景二：RL 训练到运行

1. 新建 RL 策略，选择品种、训练/验证区间、默认或高级训练参数。
2. 点击训练，任务排队执行；用户可查看真实阶段、取消、读取错误后重试。
3. 查看候选版本的结果，与规则基线比较；选择某个版本，不能只展示最优种子而隐藏其他尝试。
4. 系统将模型、特征顺序、归一化、数据版本和策略参数冻结为可运行版本。
5. 用户点击启动模拟，实例取得足够历史预热数据；就绪后按新的闭合小时 K 线运行一次决策。
6. 展示模型原始动作、新闻/风险规则作用、最终动作，以及实际订单或未下单原因。
7. 重新训练产生新候选，由用户明确选择升级。升级时旧持仓的处理方式须在规格中定义。

工程必须处理的事实：旧 PPO 没有当前行情推理链路，观察空间固定，Gym 与 Freqtrade 风控差异存在；新训练/执行协议必须明确一致部分与差异，不能把历史 CSV 直接作为在线模型输出。无需让用户选择底层库或特征数组实现。

## 场景三：新闻因子 C

1. 选择有新闻与行情重叠覆盖的数据区间，查看来源、时间可用性、币种关联和质量统计。
2. 在相同品种/区间/成本/基础训练配置下，创建“只用行情”和“行情＋新闻”的两个实验。
3. 新闻按当时可用的版本聚合成数值特征；特征应能反查来源，缺数据与零事件区分。
4. 图表和表格比较表现，并显示训练是否实际消费了新闻列。结果可以没有改善或变差。
5. 含新闻的选定模型启动模拟时，使用同一套因子语义；不允许丢弃新闻特征却显示正常运行。

候选数值：过去窗口内事件数量、事件类别数量、来源数量、距最近事件的时间、可用的情绪指标及缺失标记。具体列在数据试验后冻结，避免先设计几十个因子再发现没有数据。

关键前置验证：历史可访问性、时间字段含义、去重和修订处理、资产映射、覆盖密度、提取器的训练知识边界、线上来源与历史来源的一致性。默认不以今天的 LLM 对过去新闻的分析充当严格当时可用的特征证据。

## 场景四：多个策略与运行控制

- 实例单品种、虚拟资金独立；同品种不同策略可比较。首页汇总的是多个独立模拟实验，不暗示一个真实共享账户。
- “暂停新开仓”不停止已有持仓管理；“关闭模拟持仓”必须是明确动作，不能由打开页面或切换策略触发。
- “停止”与持仓处理的交互尚需确认；运行状态不应只按前端按钮推断，需以引擎实际反馈为准。
- 新闻、行情、模型或执行错误需要有可见状态、发生时间和原因；用户不应去终端猜测为何没有交易。
- 小时策略可能没有成交，完整流程验收采用可追溯的决策及执行状态，不以强制成交或盈利为要求。

## 四周开发顺序草案

暂按 2026-10-24 至 2026-11-20 开发，约 11 月 21 日答辩；用户只给出“四周”，准确日期未确认。下表是依赖顺序与目标，不是已完成结果或固定保证。

| 时间 | 主目标 | 阶段出口 |
|---|---|---|
| 第 1 周 | 完成需求/原型确认；验证历史新闻数据与 RL 当前推理两个关键风险；建立策略、版本、实例的最小业务基础 | 用户认可终端操作方向；新闻小样本质量报告；新闭合小时线上的冻结 RL 推理可验证 |
| 第 2 周 | 品种选择/数据准备、策略创建、训练/回测/选版本、独立模拟实例；终端显示图表与真实状态 | 用户独立完成规则和基础 RL 的主流程；暂停/恢复/异常可观察 |
| 第 3 周 | 新闻因子计算与训练集绑定、预测模型及 RL 的新闻对照、当前新闻执行规则 | 新闻实际进入训练和推理，有开关对照、有来源，不只是资讯展示 |
| 第 4 周 | 端到端联调、状态/资金/持仓核对、故障恢复、性能与交互完善 | 用户操作验收；保留可运行版本；未解决项明确记录 |

历史新闻不可用时，应在第 1 周报告具体缺口与替代数据方案、成本及影响，让用户决定，而不是到最后把 C 改成静态示例。四周优先交付核心业务，不挤入答辩材料或未确认的外围功能。

## 需求到验收的初步映射

| 需求 | 可观察的通过条件 |
|---|---|
| 独立操作 | 无需开发者后台改代码即可从选币到模拟运行；空数据时有下载操作 |
| 策略版本 | 编辑草稿不会改变正在运行的模型/参数，选定版本可以追溯 |
| 多实例 | 两个策略状态与虚拟账本独立，暂停一个不误停另一个 |
| 图表联动 | 切换实例后币种、K 线、信号、持仓与日志指向同一实例 |
| RL 真正运行 | 当前闭合 K 线有模型版本、输入时刻、动作与执行反馈，不复用历史动作伪装实时 |
| 新闻 C | 训练/推理特征清单含新闻，新闻开关对照条件一致，缺数据可见，未来/修订新闻不污染过去 |
| 新闻 B | 风险规则确实影响最终动作，界面可说明来源；原始模型动作仍保留 |
| 故障行为 | 数据源/模型/执行故障状态真实，不继续展示“运行正常” |

正式 SRS 还需补充每项状态转换、输入限制、错误恢复、性能目标与测试用例；这些应在本轮剩余业务决策确认后完成。
