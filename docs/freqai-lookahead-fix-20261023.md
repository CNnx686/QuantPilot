# FreqAI 前视诊断边界修复（2026-10-23）

## 根因

安装的 Freqtrade 为 2026.9。`data/converter/converter.py` 按 `date <= stopdt` 载入最后一根 K 线；FreqAI 的 `freqai_interface.py` / `data_kitchen.py` 按 `date < stopdt` 生成预测。`fill_predictions()` 把没有预测的末端行补成零。

上游 lookahead 为核对交易执行，主动保留成交时刻之后的一根 K 线。但它的指标检查比较整个截断表，因而把这根预测范围之外的补零行与完整回测的有效预测比较，触发 `&-return6`、统计量、`do_predict` 及衍生信号列警报。

原始诊断复现：`diagnostic-d0575a07-3957-46f0-b671-a9fb78ab3077`。6 个交易样本对应 12 次比较，差异全部只出现在 `date == cut_end`，实际入场、出场偏差均为零。日志含逐次 `BOUNDARY_PROBE` 证据。

## 修复方法与范围

新增 `quantpilot/lookahead_runner.py`，仅适用于已验证的 Freqtrade 2026.9、1h FreqAI。它复用上游交易重放和指标检测，只将指标比较范围统一为预测范围 `[start, end)`：

- 保留额外 K 线在交易重放中的作用，原始数据表不修改。
- 仅排除精确位于预测结束时刻的行；出现更晚的行、时间不对齐等异常时失败退出。
- 不对列名设豁免，预测、有效性、入场和退出信号均参与比较。
- `comparison-boundaries.jsonl` 保存每次的原始差异值、时间、比较行数和有效区间差异数；诊断报告绑定文件哈希及适配器快照哈希。
- 诊断证据数量不完整时不得判定通过；有效区间内存在任何差异时保持警报。

上游[说明](https://www.freqtrade.io/en/stable/lookahead-analysis/)提及 FreqAI 目标列可能误报，本修复没有据此忽略目标列，而是依据本机实际差异定位时间边界。

这修复的是诊断适配，策略、模型、手续费、训练窗口和交易阈值均未修改。旧警报记录保留原样。通过结论必须连同 `freqai-half-open-v1` 比较范围一起理解，不能表述为未经适配的上游检查通过。
