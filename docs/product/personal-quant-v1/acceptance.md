# QuantPilot V1：验收清单与证据要求

版本：0.1，2026-10-24。范围依据：[需求规格](requirements.md)。

实施进度更新：真实数据主流程第一批已交付，具体通过、部分通过、尚未实施的 F 用例见[实际验收记录](live-workflow-verification.md)。下表保留完整 V1 的目标与原型阶段历史要求，不把第一批闭环等同于全部 V1 完成。

2026-10-25 新闻阶段单独记录于[新闻验证记录](news-verification.md)：重点为 F-08、F-13～F-17、F-19、F-21、F-22。F-18 新闻事件风控 B 保留待实现；新闻 C 输入对照不应掺入额外执行规则。

**原型和真实功能验收必须分开：** 原型阶段验收可点击界面的布局和交互；真实功能阶段验收后端、数据、训练与模拟执行。原型示例、倒计时动画和虚拟盈亏均不能作为真实引擎验收证据。下表是完整检查模板；原型阶段实际执行的结果与未覆盖分支见[原型验证记录](prototype-verification.md)，不将部分交互通过等同于全项验收。

## 1. 原型验收 P：历史阶段

原型可以使用明确标注的演示数据，在浏览器内演示状态变化，不接交易账户、不提交真实训练、不调用付费服务。一次开始/暂停的原型点击只证明操作设计可理解。

| ID | 关联需求 | 操作 | 通过条件 | 证据 / 状态 |
|---|---|---|---|---|
| P-01 | R-01、R-24 | 打开首页 | 中文暗色终端；实例、K 线、信号/新闻、底部执行信息可辨识；原型标记持续可见 | 页面截图；待验 |
| P-02 | R-01、R-08、R-17 | 切换两个不同实例 | 品种、实例名、模型、图表与持仓/日志同步切换；各实例余额独立 | 浏览器操作记录；待验 |
| P-03 | R-02、R-03 | 新建规则 / RL / 预测策略 | 类型、品种、区间、参数、资金能填写；缺项有校验；保存后实例可定位 | 三种入口；待验 |
| P-04 | R-03、R-18 | 查看数据覆盖不足的情形 | 显示缺口与准备数据入口；模拟下载明确标注；不伪称已获得数据 | 数据面板；待验 |
| P-05 | R-04、R-05 | 打开训练/回测和结果 | 类型对应任务可见；排队/运行/失败/成功的设计明确；候选与比较可定位 | 任务与结果视图；待验 |
| P-06 | R-06、R-07 | 选择一个负收益但技术就绪的模型启动模拟 | 能进入演示运行；有原始动作、最终动作、模型版本和未下单原因 | 运行详情；待验 |
| P-07 | R-06、R-18 | 尝试启动技术不就绪实例 | 被阻止并说明数据/模型问题及下一步；不是“收益不够好” | 阻断反馈；待验 |
| P-08 | R-09 | 暂停新开仓、恢复、停止 | 状态转换明确；暂停新开仓与关闭持仓不是同一操作；仅影响当前实例 | 控制演练；待验 |
| P-09 | R-10 | 对有持仓实例选新模型 | 默认等待旧持仓结束；旧版本仍可见；提供明确关闭模拟持仓后切换选项 | 升级流程；待验 |
| P-10 | R-11、R-12、R-13 | 打开新闻因子与开关对照 | 有来源、覆盖、价格/价格＋新闻区别及输入因子说明；非 BTC/ETH 新闻限制可理解 | 新闻与实验视图；待验 |
| P-11 | R-15、R-16 | 查看新闻故障/风险拦截情形 | 区分无新闻与源故障；新开仓暂停、已有持仓继续既定风控；原始动作仍保留 | 决策解释；待验 |
| P-12 | R-17 | 操作图表与切换底部标签 | 能完成原型声明支持的缩放/拖动和标签切换；历史/模拟有明确标签 | 浏览器实测；待验 |
| P-13 | R-20、R-21 | 打开助手/设置 | 未配置状态明确，不要求聊天发密钥；核心流程可继续；没有未经配置的外部调用 | 设置视图；待验 |
| P-14 | R-24、N-06 | 查看页面标记和浏览器网络行为 | 示例数据始终可识别；操作不连接交易接口、不发送真实任务或秘密信息 | 网络与页面检查；待验 |
| P-15 | R-01、N-05 | 检查典型桌面与较窄窗口 | 关键控制可操作，内容不遮挡；不要求手机终端达到桌面全部面板能力 | 指定视口截图；待验 |

原型中尚未实现的分支应注明“设计待补 / 尚不可操作”，不能把说明文本标为交互已通过。用户认可原型表示认可其方向，不代表放弃正式能力与失败路径验收。

## 2. 真实功能验收 F：分阶段实施

需要保存任务 ID、模型/配置/数据版本、实际日志、输出或测试结果。可合并自动测试与人工业务演练，但必须指向同一实现版本。涉及新闻因子、当前推理和独立账本的项目不能只靠截图通过。

| ID | 关联需求 | 验证步骤 | 通过条件及必要证据 |
|---|---|---|---|
| F-01 | R-02、R-03 | 从空数据开始选择可支持品种，提交下载、配置、保存 | 用户无需改代码；数据覆盖通过实际检查；记录下载任务和快照 |
| F-02 | R-02、R-23 | 编辑、复制已被实验和实例引用的策略 | 生成新版本；旧配置、结果与运行引用不改变；版本指纹可核对 |
| F-03 | R-04、R-05 | 运行规则回测并检查交易明细 | 实际引擎完成，费用/资金/区间一致；结果与原始产物吻合 |
| F-04 | R-04、R-05 | RL 训练多候选并比较规则基线 | 实际模型产物存在；记录所有候选/种子及失败；比较口径一致或阻止不兼容比较 |
| F-05 | R-04、R-07 | 预测训练、选版本并当前推理 | 真实模型以已闭合数据推理；输出单位/期限明确；与模型记录对应 |
| F-06 | R-06 | 分别启动负收益就绪模型与缺少必要产物模型 | 前者可由用户启动模拟；后者明确阻止；后端同样执行检查 |
| F-07 | R-07、R-22 | 新闭合小时线到达，执行 RL 当前决策，再重复同一输入 | 有真实输入截止时间、模型哈希、原始动作和反馈；不复用历史动作；不重复下单 |
| F-08 | R-07 | 分别使用未闭合 K 线、晚到新闻、未来数据尝试推理 | 未闭合或截止后信息不参与决策；保存实际使用的输入时刻/因子快照 |
| F-09 | R-08 | 同时运行至少两个独立实例，暂停其中一个 | 余额、持仓、订单、状态隔离；另一个不被误停；汇总不冒充共享账户 |
| F-10 | R-09 | 运行 → 暂停新开仓 → 恢复；有仓/无仓分别停止 | 暂停仍执行既定持仓风控；恢复检查依赖；停止遵循已记录规则，未完成不得显示停止成功 |
| F-11 | R-10 | 有持仓时选择新版本，使用默认升级 | 原模型管理已有仓位，等待时不再新开仓；实际平仓且目标就绪后切换；有事件时间线 |
| F-12 | R-10 | 选择关闭模拟持仓后升级，注入关闭失败/预热失败 | 只有成功平仓并就绪后才切换；失败不标成功，不丢原模型与仓位 |
| F-13 | R-11、R-14 | 抽样核对新闻原始记录、归档时间、实际获取时间与修订 | 标题/来源/实体可追溯；不同时间含义明确；无当年实际接收的虚假声明 |
| F-14 | R-12、R-13 | BTC/ETH 各构建行情与新闻重叠数据，训练价格及价格＋新闻版本 | 实际输入列和模型 schema 含新闻；数据覆盖与缺口报告存在；旧维度模型不能直接加载新特征 |
| F-15 | R-13 | 运行新闻开关对照并核对基础协议 | 品种、窗口、成本、基础算法、种子协议一致；展示全部结果；收益变差也可功能通过 |
| F-16 | R-14 | 在截止前后加入迟到记录和后续修订，再计算过去因子 | 截止前因子不被污染；先 as-of 筛选再取当时最新；有固定测试用例 |
| F-17 | R-15 | 分别模拟新闻覆盖正常且无事件、采集失败、特征计算失败 | 正常无事件可为零；故障不填零并阻止新开仓；持仓既定风控继续；界面说明原因 |
| F-18 | R-16 | 触发一条新闻风险规则，再取消触发条件 | 规则确实改变最终动作；原始模型动作与事件依据保留；规则版本可查 |
| F-19 | R-12、R-15 | 含新闻模型进入当前模拟，故意移除新闻输入列 | 同一特征语义与顺序；缺列阻止继续新开仓；不得默默运行价格模型 |
| F-20 | R-17、R-18 | 图表切换、刷新、网络中断、缓存过期 | 各面板实体一致；最新时间真实；过期/部分失败不展示为正常实时 |
| F-21 | R-22、N-02 | 重复点击、重连、服务重启并核对账本 | 不重复决策/订单；恢复真实状态；资金、订单、成交与持仓能逐项核对 |
| F-22 | R-04、N-04 | 排队取消、运行取消、任务失败、刷新页面 | 取消有实际终态；失败可定位原因和重试；刷新可找回任务，不凭动画判断进度 |
| F-23 | R-19 | 在受限候选与计算预算内提交自动研究 | 实际数量不超过限制；所有尝试保留；不自动改代码、发布、替换运行版本 |
| F-24 | R-20、R-21 | 未配置、配置有效、服务失败分别操作助手 | 未配置/失败不妨碍核心流程；只辅助解释和配置；任务仍由用户触发；日志无密钥 |
| F-25 | R-23、N-01 | 迁移旧数据并执行一次回退恢复 | 原记录/产物可追溯；新旧标签准确；迁移失败不留下半成品状态 |

F-23、F-24 属于核心闭环之后的增强。DeepSeek 未在本机配置前，只能验收未配置与故障处理，不得声称官方在线接口已经验证。模型接口测试替身也不能代替真实服务可用性说明。

## 3. 研究可信度的专项门槛

- 不以“训练没有报错”证明新闻已被消费；需训练矩阵列、schema、构造日志及推理输入证据。
- 不以“模型输出变化”单独证明有效；新闻开关实验和可控输入检查服务于不同结论，应分别记录。
- 不以历史归档批次时间等同实际收到时间；归档回溯研究需记录延迟假设与敏感性检查。
- 不以回测利润为功能准入或验收门槛；亏损、波动、费用与不稳定性应保留。
- 不只展示最优种子；训练、验证、评估划分和全部候选必须可追溯。
- 对原保留评估区间不用于开发调参；需要更改协议时单独记录，不因原型演示改变协议。
- 小样本可访问性证明不能代替连续覆盖质量报告；未有合格新闻窗口时 F-14 至 F-19 不可判通过。

## 4. 故障与控制专项检查

| 故障 / 操作 | 必须保持的约束 |
|---|---|
| 用户暂停后数据源恢复 | 不自行解除用户暂停；显示依赖已恢复与当前控制状态 |
| 新闻缺失但模型提出买入 | 不绕过依赖；原始动作可看，最终新开仓被阻断 |
| 模型载入或维度不兼容 | 不使用另一个模型冒充；不启动新开仓 |
| 升级时关闭持仓失败 | 不显示目标已运行；保留旧版本、错误与实际仓位 |
| 暂停或停止另一个实例 | 不串改当前实例资金、订单或状态 |
| 行情新鲜度不足 | 不将旧快照标成最新；恢复前按技术检查决定新开仓资格 |
| 页面刷新 / 浏览器关闭 | 不被隐式解读为平仓或重新启动；服务状态仍为事实来源 |
| 原型演示完成 | 不在真实系统留下训练、运行实例或外部交易副作用 |

这些是设计与后续实现的检查约束。原型尚未覆盖的失败路径要列明，不能宣称全部验证。

## 5. 验收记录格式

每次执行建立独立记录，至少包含：

1. 日期、代码提交或构建标识、测试环境及数据模式（原型 / 固定测试数据 / 历史引擎 / 当前模拟）。
2. 用例 ID、实际操作、预期行为、观察结果、通过/失败/未测/依赖未满足。
3. 原型：页面截图、实际浏览器操作、已实现及未实现的分支。
4. 正式功能：任务/实例/模型/数据版本、日志、测试输出、产物哈希和可重放条件。
5. 已知限制与后续动作；涉及外部依赖时注明实际是否联网验证。

原型阶段完成定义：需求和页面设计可查、可点击原型可启动、主路径及明确支持的错误分支经过浏览器检查、用户能指出要改的交互。正式 V1 完成定义：核心 F 用例通过，P1 状态如实列出，用户独立走完三类策略主流程，不依靠开发者后台改代码补步骤。
