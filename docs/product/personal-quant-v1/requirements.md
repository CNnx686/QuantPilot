# QuantPilot 个人量化工作台 V1：需求规格

版本：0.1，2026-10-24。依据：用户 Q1–Q22 已确认的访谈。

状态：首版业务基线；界面细节通过本轮可点击原型继续核对。本文描述目标行为，**不是现有后端功能完成声明**。本轮交付规格、页面设计和原型；后续按阶段实现真实数据、训练与执行。

关联：[访谈记录](../../design/2026-10-24-personal-quant-discovery.md)、[业务草案](../../design/2026-10-24-personal-quant-workflows.md)、[新闻可行性](../../design/2026-10-24-news-factor-feasibility.md)、[验收清单](acceptance.md)。本文件中的 Q17–Q22 决定优先于旧草案的“待确认”描述。

## 1. 产品目标与用户

为个人使用者提供以自动策略管理为中心的量化工作台。用户无需开发者修改代码，就能完成：

**选币并准备数据 → 创建规则 / RL / 预测策略 → 训练或回测 → 比较并选定版本 → 启动独立虚拟资金模拟 → 查看决策、持仓和结果 → 暂停、升级或停止。**

首页采用中文、暗色、高信息密度的多面板终端。表单、审计和报告为具体操作提供支持，不再构成主要导航主线。强化学习、新闻和预测模型要进入同一业务链路。

首版为本机个人使用；两人团队是开发背景，不表示本期需要多租户、角色权限或多人协作平台。用户拥有所有研究与模拟操作能力。训练和运行由本机服务执行，页面关闭不应被当成停止策略的指令。

## 3. 已确认的业务决定

| 决定 | 规格约束 |

## 4. 核心对象与一致性

| 对象 | 含义及关系 |
|---|---|
| 策略 | 用户管理的逻辑容器：名称、类型、品种、研究配置；草稿可以编辑 |
| 策略版本 | 保存后的参数、风险规则、模板与代码来源快照；已绑定实验或运行时不能原地覆盖 |
| 数据快照 | 行情及新闻来源、可用区间、质量检查、时间语义、内容指纹；与任务绑定 |
| 实验任务 | 一次训练或回测；记录配置、种子、数据快照、阶段、错误、结果和产物 |
| 模型版本 | 训练产物以及特征顺序、归一化器、模型/依赖版本、训练区间和哈希；不能只有权重文件 |
| 运行实例 | 策略版本与选定模型版本的绑定，加上独立虚拟资金、持仓、订单、状态和决策记录 |
| 新闻版本与因子 | 带来源及可用时间的事件记录；因子定义有版本、覆盖质量与明确截止时刻 |
| 升级请求 | 目标版本、选定切换方式、创建时间、等待原因与最终结果；不修改历史决策 |

规则策略没有训练模型，但仍有冻结策略版本。重新训练不自动替换运行实例。新增新闻特征后必须重新训练；**旧模型的观察空间或特征维度不能被静默扩展**。

## 6. 用户主流程

### 6.1 建立并运行策略

1. “新建策略”选类型与现货品种，填写参数、资金和数据区间。
2. 数据覆盖不足时从同一流程进入数据准备；下载完成后重新检查。
3. 保存版本。规则运行回测；RL/预测先训练，再查看验证结果与候选版本。
4. 比较基线和候选，明确选定版本。数据、特征、模型不兼容会阻止继续；亏损不会单独阻止。
5. 点击启动模拟，完成预热与技术检查后进入运行；首个有效闭合 K 线到达前显示等待。
6. 选择实例查看动作、事件依据、持仓、订单和日志。没有买卖时也应有可解释的状态，不能为了演示强制成交。

### 6.2 新闻进入模型

1. 对 BTC/ETH 选择有重叠覆盖的数据；确认历史可用时间证据与缺口。
2. 创建价格基线与价格＋新闻对照。因子列与提取器版本在任务启动前冻结。
3. 结果展示总体及分段表现、输入特征、失败情况和覆盖；不宣称因果收益提升。
4. 选定带新闻模型运行时，共用训练语义、列顺序、缺失规则与截止时间；不能丢弃新闻列继续显示正常。
5. 新闻故障触发新开仓阻断；持仓继续遵守已设风控。用户可追溯模型动作、风险规则及最终决定。

### 6.3 替换模型

1. 新训练只新增候选版本，运行版本保持原样。
2. 用户选择目标版本，系统先检查兼容性与数据准备。
3. 默认模式：禁止旧版本继续新开仓，旧持仓由旧版本及既定风控管理；持仓归零后切换并记录确切时刻。
4. 显式关闭模式：用户确认对模拟持仓的影响，执行关闭并等待成功回执，确认归零后切换。
5. 关闭失败、持仓未归零或目标预热失败均不能显示切换成功；保留原有版本/等待或故障状态。

步骤 3 中“升级等待期间暂停新开仓”是防止永远无法切换的工程建议，原型应说明；并非用户另行指定的参数。

## 7. 状态与资金规则

### 策略与任务

- 草稿 → 已保存版本；修改已保存内容产生新版本，不覆盖运行引用。
- 任务：排队 → 运行 → 成功 / 失败；排队或运行 → 取消中 → 已取消。取消请求不是立即成功，已有产物标为未完成。
- 模型：候选 → 可选用 / 不兼容；“正在使用”由实例引用决定；旧候选不因另一个候选被选中而消失。

### 运行实例

| 当前状态 | 操作 / 事件 | 目标状态及行为 |
|---|---|---|
| 未启动 / 已停止 | 启动 | 检查中 / 预热中；实际满足条件后运行；失败显示原因 |
| 运行中 | 暂停新开仓 | 只管理已有持仓；继续允许既定退出与风控 |
| 暂停新开仓 | 恢复 | 重新检查依赖，成功才恢复新开仓 |
| 运行 / 暂停 | 必需新闻或其他输入失效 | 降为故障/阻断新开仓；保留持仓风控，不隐式换模型 |
| 有持仓 | 选择默认升级 | 等待平仓；旧模型管理持仓，空仓且新版本就绪后切换 |
| 有持仓 | 明确关闭后升级 | 关闭中 → 实际空仓 → 切换；失败保留错误及原版本 |
| 空仓 | 停止 | 停止中 → 已停止；依据服务反馈结束，不影响其他实例 |

**停止细则为工程建议，待原型评审：** 有持仓时，“停止”默认进入“等待平仓后停止”，暂停新开仓并继续风险管理；可另选明确关闭持仓后停止。避免留下无人管理仓位，也不静默平仓。“停止”不删除记录、不重置资金；重新运行资金如何延续要明确显示。故障恢复建议先恢复数据检查，保留用户暂停标记，不自行解除用户暂停。

本期没有自由输入价格/数量的手动买卖终端。显式关闭模拟持仓属于策略运行控制。模拟费用、滑点、仓位约束和资金单位必须在配置与结果中一致展示；具体默认数值是工程设定，不视为用户收益目标。

## 8. 新闻数据可行性与时间约束

已验证事实仅是两份 GDELT 历史归档可读取并有相关标题，详见可行性文档；**没有证明连续覆盖完整、资产分类正确或足够训练**。首阶段必须先验证一个受控连续窗口，记录下载量、覆盖、去重、资产映射与质量。不可用时明确说明受限区间及影响，不能把 C 偷换为静态新闻展示。

- 分离源声明时间、归档批次时间、本机实际收到时间、处理完成时间与证据质量。
- 历史归档按明示延迟假设进行回溯研究；不能声称本平台当年实际收到过消息。延迟假设必须可复查。
- 当前收集记录实际到达与处理时刻；闭合 K 线决策不能使用决策后才可用的信息。
- 今日 LLM 提取可能含后续事件知识，首批优先冻结可解释规则/归档字段；不可包装成严格当时可用特征。
- 有覆盖但无事件允许计数为零；覆盖缺失不是零新闻，未知情绪不是中性。
- 首版优先必要标题、事件和来源元数据，不把整篇新闻抓取/再分发作为默认范围。
- 原项目已预留的最终评估区间继续保留；开发不动用它反复试验。历史可访问性探针不是允许使用该区间训练。

## 9. 非功能约束与验证原则

| ID | 要求 | 验证方式 |
|---|---|---|
| N-01 | 旧配置与产物可追溯、可回退，升级不丢历史记录 | 迁移前后记录与哈希对照；备份恢复演练 |
| N-02 | 重复点击、刷新、服务重启不重复执行模拟订单；状态经恢复核对 | 幂等、断连/重启故障测试 |
| N-03 | 前后端都校验输入与依赖；前端按钮不是唯一业务约束 | 绕过 UI 的接口测试及正常 UI 流程 |
| N-04 | 主要任务可观察且长任务不冻结工作台；刷新后能找到原任务 | UI 任务恢复与并行浏览验证；实机测量耗时 |
| N-05 | 页面可辨识加载、空、旧数据、部分失败、阻断与停止状态 | 原型评审加真实失败场景 |
| N-06 | 原型和真实结果显著区分；不伪造实时、训练进度或订单 | 文案、来源标记及网络行为检查 |

本机资源上限、并发训练数、最大并行实例数、轮询周期、新闻过期阈值和精确响应时间尚未实测；先给合理可见默认值，在后续技术设计和基准中确定。不可把原型的秒级演示速度当成真实训练速度。

## 10. 本轮交付与未冻结项

本轮应交付：本文、需求对应验收表、页面结构、实施阶段计划、可点击原型。原型用于确认工作台布局、创建流程、训练比较、新闻影响、运行控制和升级行为，不代表真引擎接入。
