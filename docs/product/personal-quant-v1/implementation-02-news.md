# 第二批：新闻事件因子进入模型

2026-10-25。基于 `b56d8ba`，分支 `feature/news-event-factors`。使用 andrej-karpathy-skill、executing-plans / subagent-driven-development、quantpilot-evaluation；用户授权自主实现。保留旧价格引擎三文件与模型哈希，新增新闻引擎，避免旧账户失效。

## 方案与可检验边界

- 免费 GDELT GKG 标题元数据，按 UTC 00/06/12/18 固定六小时采样；每份档案只代表一个 15 分钟批次，不声称收集了中间所有新闻。首期 BTC/ETH、14～31 天；不取 2025 Q4。
- 四个输入为 24 小时采样事件数、来源数、监管事件数、安全事件数的 log1p，明确资产词规则与版本。无合格覆盖不填零；有覆盖无匹配事件可为零。
- 历史可用性为归档批次 + 1 小时假设，真实下载时间另存；当前输入取本机解析完成时刻与批次+1小时较晚者。先筛 available_at，再选当时最新版本。首次采集不能用于已过去的闭合线，只能等待下一根合格线。
- 新闻开关配对任务共享市场快照、时序切分、参数、种子、资金、手续费与计算预算，只增新闻列。额外新闻 B 风险规则不加入本轮，以免把执行规则的影响误归因于训练特征；此功能仍为后续需求。
- 当前新闻故障阻断新闻模型新执行，不代用价格模型；已有仓位继续既定价格止损。完整记录新闻列、事件ID、覆盖及可用时刻。
- 首次有效输入之前可等待自动就绪。已经有效运行后发生新闻故障则锁定人工恢复，覆盖恢复也不自行开仓；用户主动暂停标记始终保留。预测只读已观测缓存，下载由独立后台采集器执行。

## 工作分解

- [x] 数据与因果层（root）：受限下载、缓存和版本、历史包、当前采集、按截止聚合、覆盖检查、来源证据与核心测试。
- [x] 新闻引擎（engine）：独立 schema、LightGBM/PPO、维度与归一化、同一特征逻辑、冻结证据、训练标签 purge、旧模型兼容。
- [x] 任务/账本（backend）：开关校验、同源配对、失败/取消保留、候选归属、当前冷启动/故障恢复及持仓风控。
- [x] 前端（frontend）：新闻配置、真实事件与覆盖、配对指标/净值、输入列与决策事件关联、等待/故障状态。
- [x] 根集成：实际 BTC/ETH 新闻获取；两算法各跑新闻开关对照；新模型真实当前推理与模拟；旧账户兼容；独立规格/质量复核、全回归、浏览器操作和说明文档。真实 2026-10-25 05:00 UTC 闭合线已由两个新闻模型消费；人工暂停保持、恢复和同小时去重通过，详见[验证记录](news-verification.md)。
