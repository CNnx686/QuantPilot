# QuantPilot MVP2 Implementation Plan

> Use subagent-driven-development: sequential implementers, spec review then quality review. User delegates design decisions and implementation. Do not enable real accounts or submit real orders during development.

**Goal:** Deliver exchange market monitoring, traceable news research, executable PPO research and an independently gated live execution control plane.
**Architecture:** Preserve MVP1 artifacts and simulation policy. Add bounded persisted jobs and isolated modules; Freqtrade remains the only exchange order writer. Existing flagged ML remains blocked. Final holdout remains untouched.
**Tech Stack:** Existing FastAPI/React/SQLite/Freqtrade 2026.9/CCXT4.5.85; isolated RL runtime with pinned SB3/torch/Gymnasium after compatibility probe.

## A. Public data and news services
- [ ] Add exchange public adapters for Binance/OKX/Kraken, cached snapshots, precision/limits and explicit capability states, bounded refresh jobs, no private calls. Preserve source identity and stale/error states.
- [ ] Add allowlisted RSS sources, bounded nonredirecting fetch, safe XML/HTML text, immutable article versions, timestamps, deduplication, persistent refresh status; optional explicit bounded DeepSeek analysis plus offline extraction labeled honestly; research draft linkage retains article version.
- [ ] Add tests for source separation, stale/error states, unsafe URLs/content, duplicate/revised news, time availability, idempotency and no secrets. Document API contract. Spec then quality review.

## B. RL research
- [ ] Build isolated pinned environment, inspect installed FreqAI hooks and train bounded PPO on actual prior market data. Fixed temporal training/validation and seeds, no holdout access.
- [ ] Implement persisted jobs, model/artifact hashes, raw rewards/actions, cost-aware environment, deterministic evaluation and actual Freqtrade action replay where supported. Report environment/execution differences, no fabricated profitability or deployment approval.
- [ ] Expose readiness/train/results APIs with bounded resources/cancellation and tests for temporal leakage, invalid actions and job recovery. Spec then quality review.

## C. Live control and risk
- [ ] Implement independently authenticated preflight/command journal, credential references, account-scoped budgets, separate live policy, Freqtrade submission path risk hooks and reconciliation states. Default disabled; no account credentials required for offline verification.
- [ ] Preserve explicit distinction between verified code, fixture/testnet evidence and unverified real venue behavior. Unknown/missing evidence blocks activation. User owns local credential enrollment and explicit activation.
- [ ] Test idempotency, stale credentials/config, precision/budget/quote checks, partial-fill reconciliation, timeout unknown handling, stop vs liquidate semantics. Spec then quality review.

## D. Product and acceptance
- [x] Add ExchangePanel, NewsPanel, RlLabPanel, LivePanel with genuine API data and clear modes. Integrate news research, reports and overview without changing original artifacts.
- [x] Run full backend tests, frontend build, public network probes, actual bounded PPO training, browser workflows; record exact successes and external blockers.
- [x] Update startup/runtime scripts, user guide, acceptance, progress and known limits. Review and commit final verified version; keep MVP1 tag.

Concrete interfaces and test cases are finalized in each module contract before dependent frontend work; see design/2026-10-15-mvp2-expansion.md for source research and detailed semantics. Completion requires recording actual coverage; a disabled placeholder is not a completed live execution system.
