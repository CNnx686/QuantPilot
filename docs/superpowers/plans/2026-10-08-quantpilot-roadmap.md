# QuantPilot 五周开发与答辩计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在约 2026-11-12 的答辩前完成可复现、可演示的 AI 量化研究与模拟交易应用，由 AI 承担主要开发，两位成员负责业务确认、验收及答辩。

**Architecture:** 采用自建业务前端与 FastAPI 后端，后台任务调用固定版本的 Freqtrade/FreqAI。数据、策略、实验和交易通过版本化标识关联；RD-Agent/Qlib 以独立研究任务接入，不作为核心展示链路的前置依赖。

**Tech Stack:** React、TypeScript、FastAPI、SQLite、Parquet、Freqtrade/FreqAI、LightGBM、Docker Compose、大模型 API。具体依赖版本在环境预检后锁定，不使用浮动 latest 作为交付版本。

## 1. 文档定位与工作方式

这是跨子系统的范围、架构、里程碑及验收总计划。业务与运行环境尚未验证，不预写整个应用的假定代码。实施时按数据与实验、AI 研究、模拟交易、展示与交付四个子系统分别编写包含准确文件和命令的执行计划，然后逐项实现、测试、集成。

当前只创建计划文档，尚未安装依赖、连接交易所、调用付费模型、训练模型或实现应用。

开发在本聊天的主动工作回合中推进，不意味着会在未来五周无人触发时持续后台运行。每次结束更新进度文件，下一次从最近通过验收的版本继续。

## 2. 默认范围

- 演示资产：BTC/USDT、ETH/USDT，固定品种，1 小时 K 线，现货、只做多、虚拟资金。
- 数据：选择一个当前可访问的数据源；记录来源、获取时间、时区、缺失段、校验摘要和使用条件。具体交易所尚未选定，第一批开发先验证数据可用性。
- 历史范围：优先准备 12—24 个月完整数据，最终跨度由可用性决定，并在任何选参前冻结训练、验证、最终测试区间。
- 核心模型：LightGBM，CPU 优先；无需把本地训练大语言模型纳入首版。
- 业务界面：中文、桌面浏览器优先，单机演示，不做多租户与复杂用户权限。
- 默认运行模式为模拟交易。历史回放、回测、实时模拟三种模式在界面上明确区分。

不纳入五周必交付：真实资金交易、杠杆合约、高频订单簿、强化学习、新闻抓取平台、移动端、多交易所路由。

## 3. 业务状态与数据契约

研究流程：草稿 → 配置确认 → 排队 → 运行 → 成功/失败/取消 → 验证 → 发布或驳回。

任务状态与策略发布状态分别存储。训练成功不等于策略合格，策略合格也不意味着未来盈利。

### 统一实体

| 实体 | 最少字段 | 作用 |
|---|---|---|
| DatasetVersion | id、source、pairs、timeframe、start、end、timezone、checksum、quality_report | 数据快照 |
| ResearchSpec | id、hypothesis、features、model、prediction_horizon、strategy_rules、split_id、cost_config、risk_config | 确认后的研究配置 |
| Experiment | id、spec_id、dataset_id、code_revision、seed、status、artifact_paths、metrics、error | 可复现实验 |
| StrategyVersion | id、experiment_id、feature_version、model_artifact、config_hash | 发布对象 |
| ValidationReport | id、strategy_version、checks、thresholds、pass、reasons | 规则化发布依据 |
| Deployment | id、strategy_version、mode、status、started_at | 模拟运行实例 |
| DecisionEvent | id、deployment_id、candle_time、prediction、entry_conditions、risk_checks、decision、order_reference | 决策证据 |

预测数值不标注为概率，除非模型输出与校准确实支持概率解释。UI 不把资金曲线解释为收益保证。

### 接口约定

业务后端提供 /api/research、/api/experiments、/api/strategies、/api/deployments、/api/replay、/api/reports。创建操作返回任务或实体 ID；长任务通过查询任务状态和事件流呈现进度。进度无法估计时展示阶段名称，不编造百分比。

前端不直接持有交易服务凭据。后端用适配器调用 Freqtrade REST API；训练和回测通过固定参数的后台进程或独立容器执行，不将自然语言拼接为 shell 命令。

## 5. 分阶段任务与验收

### 阶段 A：环境与真实回测，10 月 9—15 日

- [ ] 检查 Python、Node、Docker/WSL 可用性、CPU/内存/磁盘；记录部署方式，不自动安装大型系统组件。
- [ ] 验证行情获取和历史覆盖，保存数据快照及质量报告。
- [ ] 创建项目骨架、数据库实体、任务状态和独立工作进程。
- [ ] 跑通一条规则基线策略，解析真实回测产物。
- [ ] 实现网页创建实验、查看状态、失败原因及结果。

验收：网页提交 → 后台真实执行 → 结果入库 → 刷新仍能查看；相同数据和配置可重复运行。失败任务不能显示为成功。基线回测保存全部成交及费用设置。

### 阶段 B：机器学习与一致评测，10 月 16—22 日

- [ ] 接入 FreqAI 与 LightGBM，定义未来若干根 K 线的收益目标和当前可用特征。
- [ ] 按时间滚动训练与验证；训练窗口尾部剔除标签跨出边界的样本，预处理只拟合训练数据。
- [ ] 固定策略执行时点，收盘后可用信号不能按已过去的价格成交。
- [ ] 实现规则策略与基础 ML 策略的公平对比。
- [ ] 展示扣费后结果、最大回撤、交易次数、换手、分阶段表现和数据覆盖。

验收：最终测试区间不参与调参；回测中的模型只用当时已获得的数据训练；指标可从交易记录重新计算。费用使用引擎配置，滑点压力分析明确建模方法，不能声称引擎默认已完整模拟滑点。

### 阶段 C：AI 研究与模拟交易闭环，10 月 23—29 日

- [ ] 大模型将需求转为受 schema 约束的 ResearchSpec，用户可修改确认。
- [ ] 模型只能选择已实现的特征与策略模板；无效配置明确返回错误。
- [ ] 发布规则包含数据检查、足够的评估样本、预设风险阈值和完整产物；不足时状态为证据不足，不能自动放行。
- [ ] 发布固定策略版本到 dry-run；初版由用户点击发布。
- [ ] 接入运行状态、余额、持仓和交易记录，为信号与风控判定增加 DecisionEvent。
- [ ] 实现暂停新增开仓，并明确已有持仓继续按原规则管理；停止进程与平仓不混为一个按钮。

验收：能从输入需求走到模拟运行；能演示被发布规则驳回的策略；每个交易信号可追溯到数据时间、模型版本和条件。大模型不可用时，手动配置仍能跑通核心业务。

### 阶段 D：演示体验与可选研究模块，10 月 30—11 月 5 日

- [ ] 用已完成真实实验的事件实现时间排序、暂停、倍速历史回放，明确标注运行来源。
- [ ] 实现依据结构化记录生成复盘报告，数值来自工具计算，文字解释引用交易或实验 ID。
- [ ] 核心闭环全通过后，给 RD-Agent/Qlib 集成最多两个工作日的探索预算。
- [ ] 可选集成验收：在同一行情快照生成一个候选因子，在适配前后核对值、缺失值和时间戳，由 FreqAI 重训并完成独立回测。
- [ ] 集成未达到验收标准时移出主展示，保留问题记录；不把自建助手称为 RD-Agent。
- [ ] 完成彩排，11 月 5 日冻结功能。

验收：无网络时可查看真实已完成实验并回放；完整流程能在 8 分钟内讲清楚；不能将预录结果标成当前新任务的输出。

### 阶段 E：交付与答辩，11 月 6—12 日

- [ ] 修复阻断缺陷，固定依赖、数据、模型与演示版本。
- [ ] 准备一键启动说明、环境预检、数据备份和演示录像。
- [ ] 完成架构图、ER 图、业务状态图、实验结果表、开源归属与贡献说明。
- [ ] 完成 PPT、答辩讲稿和问题清单；双方均能解释一笔交易的完整路径。
- [ ] 在实际答辩电脑至少执行两次从启动到结束的彩排。

## 6. 两人团队与 AI 分工

AI：主要代码、接口、测试、调试、文档、演示数据整理及技术讲解。每批工作提交可运行结果、检查证据和下一步记录。

成员 A：产品与演示负责人。确认页面和流程，验收交互，维护 PPT 主线与现场操作脚本。

成员 B：实验与技术负责人。确认研究假设、实验条件、数据解释，核对指标和图表，维护论文/报告技术部分。

双方：每周审阅一次真实运行结果；在使用 AI 生成内容时遵循学校规则，并能如实解释技术来源与个人工作。AI 辅助开发不代替理解与事实核对。

建议每人每周为确认、验收、学习与答辩材料预留 4—6 小时；该时间是规划假设，不是已经确认的可投入时间。

## 7. 质量验证与降级规则

- 测试重点：时间泄漏、费用计算、状态迁移、结果关联、风险拦截、失败恢复、真实业务路径。静态展示内容无需机械地逐项写测试。
- 数据接口不可用：优先使用可合法保存和复现的本地历史快照，完成离线研究与回放；真实行情接入单独标记可用状态。
- LLM 不可用：保留手动配置入口，历史 AI 方案标记为已保存方案；不伪装成新的在线生成。
- 算力不足：缩小研究窗口与候选数量，优先 CPU 树模型，不降低时间划分与数据质量要求。
- 回测不盈利：如实展示失败案例和模块增量，不反复挑最终测试集直到得到好看的曲线。
- 延期优先删除：新闻模块、RD-Agent 深度适配、多模型搜索、视觉装饰；保留核心闭环、决策记录和真实结果。
