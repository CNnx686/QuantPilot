# QuantPilot MVP1 使用手册

本版本面向两人课程项目与现场答辩，提供完整的本地研究流程：研究配置 → 历史实验 → 同条件对照 → 发布审计 → 虚拟资金模拟 → 历史回放 → 研究报告。运行目录为 `D:\QuantPilot`。

## 启动和停止

当前电脑依赖与历史数据已准备。双击根目录的 `launch.cmd`；服务启动成功后自动打开 http://127.0.0.1:8765/ 。也可在 PowerShell 中运行 `start.ps1` 并手动打开网页。关闭网页不会停止后台服务。

双击 `doctor.cmd` 进行只读本地自检；脚本不会启动交易、调用大模型或下载数据。机器可读结果：`doctor.cmd --json`。`launch.cmd --no-browser` 只启动服务，便于检查启动结果。

退出演示后，在 PowerShell 运行 `stop.ps1`。它停止托管模拟引擎和实验服务，已完成记录保留；正在执行的实验会被标为中断失败。停止模拟引擎不会自动平仓，也不会继续管理仓位。

新电脑先安装 Python 3.13、Node 22 和 uv，然后在项目根目录运行 `setup.ps1`，准备锁定依赖、公开历史行情和前端构建。首次安装需要网络与足够磁盘空间；仓库不自带历史工件、模型、虚拟环境或你的密钥。当前机器的启动验收不能替代新电脑验收。

## 第一次体验：先走通一个研究

1. 在总览查看本地就绪状态，再进入研究助手。
2. 选择本地模板，输入 `BTC ETH SMA trend baseline`。本地模板不调用在线大模型；也可选择已配置的 DeepSeek。
3. 审阅或修改名称、假设、策略、日期、资金与费用，保存草稿。确认所保存版本后才会创建实验；已确认记录不能改写。
4. 到实验工作台观察排队、运行、成功或失败。回测仍需要公共交易所元数据网络连接，耗时没有保证。可以查看日志，不会显示虚假进度。
5. 实验成功后查看成交和余额，并进入研究报告。报告核对原始工件，提供 HTML 和 JSON 下载；HTML 可用浏览器打印为 PDF。

在线模型只负责受 schema 限制的配置建议，不生成或执行任意策略代码，也不直接下单。未配置或失败时仍可使用本地模板；不会自动付费重试。密钥只放在本机 `.env`，参考 `.env.example`，不要放到前端或投屏。

## 五分钟快速浏览已保存成果

- 实验对照：选择验证区间的 `week2-validation-SmaTrend` 和 `week2-validation-FreqaiTrend`。只能比较相同数据、时间、资金与成本条件。现有候选 ML 没有超过 SMA 基线。
- 发布审计：查看开发 SMA 的通过记录，以及开发 ML 的拒绝记录。最终未见测试仍未验证，教学模拟门槛不等于盈利认证。
- 历史回放：选择已有完成实验，播放、暂停、倍速或单步查看。时间始终是原始 UTC；播放速度只改变事件展示速度，不产生订单。
- 研究报告：选择同一实验，查看指标、研究关联、原始诊断与发布记录，再导出 HTML。未记录的风控原因不编造，未定义指标不当作零。

只读总览、自检、报告、已保存结果与回放不依赖外部网络。新的历史实验、当前行情模拟及在线建议各有外部网络依赖；没有网络时不要把旧快照称为实时状态。

## 模拟交易的操作含义

只有通过审核且启动时哈希复核一致的 SMA 可创建部署。每次创建独立虚拟账户和私有运行目录，不接收交易所账户密钥。新实例初始暂停开仓；实际引擎配置和健康处理时间核验成功后，才出现恢复入口。

| 操作 | 实际含义 |
|---|---|
| 恢复运行 | 允许按策略产生新开仓，仍使用虚拟资金 |
| 暂停新开仓 | 不增加新仓位，已有持仓继续按规则管理 |
| 停止引擎 | 停止进程和持仓管理，不强制平仓 |
| 历史回放 | 只读历史成交，完全不控制引擎 |

小时策略在短时演示中可能没有成交。信号观察不等于已完成订单，不为演示强制制造订单。网络故障或已停止实例的保存快照会标记过期。

## 读懂报告

净收益率已经扣除回测配置中的交易手续费；余额曲线是已实现余额，回撤为引擎已平仓账户口径，不是包含浮动盈亏的逐时净值。费用敏感性表为固定成交路径后处理，不能声称已完整模拟滑点与冲击。

报告导出前验证原始 ZIP 与保存结果一致，附带来源哈希及原始 UTC。报告是导出时刻的证据汇总，之后新建的审核不会自动写进旧下载文件。出现工件缺失或损坏会拒绝报告，而不是编造数据。

ML 原始前视诊断 `flagged` 尚未解决，当前模型只用于历史研究。16 折特征与可知标签补充核对不等于全局无泄漏证明；历史回放成功也不会清除告警。最终测试 2025Q4 未下载、未运行。MVP1 不包含实盘、杠杆、新闻策略或 RD-Agent/Qlib 集成。

## 保存、备份和故障处理

代码在 Git 中；大文件和个人配置不入库。完整本机备份需要保留 `data/`、`artifacts/`、`runtime/` 和 `.env`。应先停止服务再复制数据库，避免复制到写入一半的状态。`.env` 及私有部署配置含凭据，不应作为公开答辩附件。

- 页面打不开：运行 `doctor.cmd`，确认前端已构建，然后运行 `launch.cmd`。端口冲突时不要关闭不属于本项目的进程。
- 实验停在队列：检查执行器；启动服务恢复执行器。错误日志在实验详情和 `runtime/`。
- 在线建议失败：切换本地模板，保持明确来源标记。
- 模拟不可用：保留错误状态，检查公共网络；历史回放和报告仍可用于展示。
- 报告证据异常：恢复原始工件或重新运行实验；不要修改结果数字来绕过检查。

## 两人答辩与后续反馈

成员 A 负责需求、配置确认、界面、审核与报告导出；成员 B 负责数据时间、模型评估、执行模式和证据边界。双方都能解释一笔交易来自哪个实验，以及为何能/不能发布。

Freqtrade/FreqAI 提供交易、回测与训练框架，LightGBM 提供回归，DeepSeek 提供配置建议。项目自研贡献为中文工作流、结构化配置确认、隔离任务、时间边界处理、审计、模拟适配、证据回放和报告；不是自研交易引擎或基础大模型。

下一轮反馈可以直接描述：哪个页面难用、缺少哪个业务动作、哪段答辩逻辑不清楚。MVP1 固定后再逐项改进，避免把未验证的新功能混入当前展示版本。
